Builder note for `docs/design/0.6.1-brief.md`. HEAD at build time `3ed513e`
(the first pass was built against `f0ab293`; this rework folds in the two
brief moves since then - Part D became a fix, and Part C must leave the

## A. `answers` agrees with the resolver

`resolve.drafts_to_fields`, in the field assembly. `decision` is the resolver's
mark decision (`_geometric_mark_decision`, then `_apply_declared_convention`).

| resolver outcome | `answers` | model original kept? |
|---|---|---|
| `auto_select` / `declared_convention` (the resolver selected) | exactly the selected options' texts, **in option order** (`selected`) | yes, on new `Provenance.model_answers`, only when the model's own `answers` were non-empty and differed |
| `ambiguous` / `declining` | unchanged - the model's `answers` stand | no |
| no decision (no marker on the row) | unchanged | no |

`value_raw` is unchanged (`selected` join for a selection, `draft.answers` for a
`text` field or an unselected select) and is already consistent with
`options[].selected`, so Part A moves only `answers`. `ambiguity` is **not** set:
the resolver is confident, so `FieldAmbiguity` ("the value could not be resolved
unambiguously") does not fit; the existing model-vs-geometry disagreement check
already sets `review_reason = AMBIGUOUS_MARK` where the model's `selected`
flags contradict the resolver. The model's original is kept via the new
`Provenance.model_answers: list[str] | None` member (omit-if-default, exactly
the `stated_control_type`/`kind_rule` shape), so no `Field` member was added.

Hand-derived table (the tests in `tests/test_061_answers.py`; fixtures are
hand-typed elements through `analyze`, one row unless noted):

| case | row | convention | model selected / answers | resolver | `answers` | `value_raw` | `provenance.model_answers` |
|---|---|---|---|---|---|---|---|
| a | `Q \| Yes \| X \| No` | mark_follows | No / `["No"]` | declared_convention -> Yes | `["Yes"]` | `"Yes"` | `["No"]` |
| b | `Q \| Yes \| X \| No` | none | No / `["No"]` | ambiguous (BETWEEN) | `["No"]` | `None` | `None` |
| c | `Q \| A \| X \| B \| C` | mark_follows | B / `["B"]` | declared_convention -> A | `["A"]` | `"A"` | `["B"]` |
| d | `Q \| A \| B` | none | A / `["A"]` | none | `["A"]` | `"A"` | `None` |
| e | stacked multi Alpha/Beta, both marks | none | - / `["Alpha"]` | auto_select -> Alpha, Beta | `["Alpha","Beta"]` | `"Alpha, Beta"` | `["Alpha"]` |
| f | `Q \| Yes \| X \| No` | mark_follows | Yes / `["Yes"]` | declared_convention -> Yes | `["Yes"]` | `"Yes"` | `None` |

Mutation guard: `test_override_removed_would_leave_the_models_wrong_answer` (a
build with the override dropped leaves `answers == ["No"]`).

**Interpretation.** The brief's first bullet reads "if the resolver selected
options, `answers` becomes exactly the selected options' texts". We implemented
it unconditionally: **under the `lines` contract too**, a field the resolver
selects now carries the selection on `answers`. The reviewer's "under `lines`,
`answers` stays `[]`" describes the pre-fix state; Part A's whole point is that
`answers` agree with `options[].selected`, and on `lines` the model never states
`answers`, so the mirror is the only claim. No score moves: the gold scorer
reads `answers` only for `kind == "text"` fields, which have no option
selection.

## B. No silent empty label (`lines`)

`resolve._draft_from_record` (the lines draft builder), after the `L=` cells
build the label. `_sole_row_text_cell` collects every cell of the cited `L=`
rows whose `strip_marks` text is non-empty.

| case | label | the promoted cell | review |
|---|---|---|---|
| label non-empty | unchanged | - | unchanged (`record.review`) |
| label empty, exactly one non-mark text cell on the cited row(s) | repaired to that cell's text | dropped as an option/answer/note; added to the label refs (`source_elements`) | `review_reason = AMBIGUOUS_ROLE` |
| label empty, zero or >=2 such cells | stays `""` | - | `review_reason = AMBIGUOUS_ROLE` |

Hand-derived (the tests in `tests/test_061_empty_label.py`; the row is
`X | Locked Rollup Count`, `s` = lattice coordinates):

| reply | `label_text` | `options` | `answers` / `value_raw` | review |
|---|---|---|---|---|
| `bool L=<text> O=<mark>` | the text | `[]` | `[]` / `None` | unchanged (the field's own mark still flags it) |
| `bool L=<mark> O=<text>` | the text (repaired) | `[]` (no longer an option) | `[]` / `None` | flagged |
| `text L=<mark> A=<text>` | the text (repaired) | `[]` | `[]` / `None` (no longer the answer) | flagged |
| `bool L=<mark> O=<a>,<b>` (two text cells) | `""` (not repaired) | `[a, b]` | `[]` / `None` | flagged |

Mutation guard: `test_repair_removed_would_leave_an_empty_label` (a build with
the repair dropped leaves `label == ""`).

**Answer decision (`text L=<mark> A=<text>`).** The promoted cell becomes the
label and is **no longer the answer**: `answers == []` and `value_raw is None`.
A cell is never both `L` and `A` - the lines parser already enforces "an element
is never both L and O" (`lines.py`), so the repair extends the same rule to
`A`/`N`. Keeping the answer would emit the text twice (once as an unusable empty
label, once as the value) and leave the field unlocatable, which is the defect.
The cell is still the field's evidence (it is in `source_elements` as the label
ref), so nothing is lost.

**Interpretation of the brief's rule.** The brief says the candidate is "a
non-mark text cell that is not otherwise cited as an option, answer or note",
but its own pinned outcomes contradict that literally: in `bool L=<mark>
O=<text>` and `text L=<mark> A=<text>` the single text cell *is* cited (as O/A)
and the brief still repairs it. We read the clause as the **post-condition** -
after the repair the promoted cell ends up cited as `L` only - so the operative
test is "exactly one non-mark text cell on the cited row(s)".

## C. Per-tab outcome in coverage

`model.TabCoverage` gains two members (plain defaults, matching the 0.6.0
coverage additions):

- `dispositions: int = 0` - the number of **distinct lattice rows** the tab's
  model `hdr`/`note`/`skip` records addressed. `compute_coverage` groups the new
  `Disposition.page` (carried from the projection chunk) by page.
- `model_declined: bool | None = None` - `True` when the tab has anchors, the
  model returned at least one disposition, and the tab has no field; `False`
  otherwise; `None` under `json` (`compute_coverage(dispositions=None)`).

`Disposition` gained `page: int | None`. `pipeline.run` collects the
dispositions for the `lines` contract (both the fresh path and the reuse path's
fresh authoring) and passes them to `compute_coverage`. Part C changes no
`InstanceStatus`, no `min_coverage` semantics and adds no error.

Hand-derived (the tests in `tests/test_061_model_declined.py`; a tab of six
anchor rows `Label Row NN | X`):

| reply | fields | `dispositions` | `model_declined` | status |
|---|---|---|---|---|
| `hdr L=0.0` + `skip L=1.0` | 0 | 2 | `True` | PARTIAL (the pre-existing no-fields rule, not C) |
| `bool L=0.0 O=0.5` | 1 | 0 | `False` | COMPLETE |
| `bool L=0.0 O=99.9` (unresolved ref) | 1 | 0 | `False` (anchors present but unbound) | - |
| `end` only | 0 | 0 | `False` (an empty reply returned no disposition; a different failure) | PARTIAL |
| `json` contract | - | 0 | `None` | - |

**SCHEMA stays "2" (not a bump).** `TabCoverage` is serialised into
`InstanceRecord`, but both new members are `omit_if_default` (`field(default=0,
metadata={"omit_if_default": True})` / `field(default=None, ...)`), so a `json`
run - where `dispositions` is `0` and `model_declined` is `None` - omits both
and its dump is 0.6.0's byte for byte. `test_json_coverage_serialises_to_the_
pre_0_6_1_bytes` compares a json run's serialised `TabCoverage` to the same
record's 0.6.0 field set. So `SCHEMA_VERSION` stays `"2"` and no instance key
moves for C. The `lines` contract *does* gain one byte: `model_declined` is
`False` (not `None`) on a lines tab that has a field, so it is emitted. That is
a real, intended C byte on the lines path only; the brief requires byte-identity
for `json`, not for `lines`. (A cached 0.6.0 *lines* instance is served until
`force=True` or another byte changes - noted, not fixed.)

## D. A stray mark must not null a TEXT answer (fix)

`resolve.drafts_to_fields`. After the geometric mark decision and any declared
convention, a `control_type is ControlType.TEXT` draft's decision is cleared
before any decision branch. A TEXT draft has no options, so a mark cannot select
anything; leaving the decision in place nulled `value_raw` and set an ambiguity
on a text field whose typed answer bound fine.

| resolver outcome | before | after |
|---|---|---|
| a mark on a TEXT row | `value_raw = None`, `value_normalized = None`, `ambiguity` set (`competing_options` with no convention; `convention_unsupported_by_geometry` with `mark_follows_option`), `review_flag` `AMBIGUOUS_MARK` | decision cleared: `value_raw`/`value_normalized` follow `answers`, `ambiguity is None`, no review flag |
| `single_select`/`multi_select`/`bool` | a mark is the control's state | **unchanged** |

Hand-derived (the tests in `tests/test_061_characterise.py`; a `Pipeline` run
with a scripted `lines` client on a synthetic workbook; the text row is
`mark | Fee Description | Administrative charge`, reply `text L=0.1 A=0.2`):

| row | glyphs | convention | `answers` | `value_raw` | `ambiguity` |
|---|---|---|---|---|---|
| `X \| label \| answer` (six combinations) | `X`, `☒`, `✓` | none / `mark_follows_option` | `[answer]` | `answer` | `None` |
| `Rounding \| Yes \| X \| No` | `X` | none | `[]` | `None` | `between_options` |
| `Rounding \| Yes \| X \| No` | `X` | `mark_follows_option` | `["Yes"]` | `"Yes"` | `None` |
| `Fee Description \| X` (answer cell is the mark) | `X` | none | `[]` | `None` | `None` |
| `Fee Description \| X answer` (mark inside the answer cell's text) | `X` | none | `[answer]` | `answer` | `None` |

Mutation guard: `test_the_guard_widened_to_selects_would_erase_the_ambiguity` -
widening the guard to `single_select` leaves the no-convention select row with
`ambiguity is None`, so the test fails.

**What a reply must look like for the typed answer to bind.** `text
L=<label-cell> A=<answer-cell>` on a `text` field, with the row's mark a
separate cell (or embedded in the answer cell): `value_raw` is
`draft.answers[0]`, i.e. the citing of `A=` is what binds it. The shape is a
`text` reply; a `single`/`bool` reply that puts the value under `O=` reads it as
an option instead and still gives `value_raw is None` (a select with no
selection is unselected) - that is the model choosing the kind, not a resolver
loss.

## Open findings / decisions

1. **B rule wording vs its pinned outcomes** - resolved as the post-condition
   reading above. No decision needed unless the reviewer intended a hard
   exclusion.
2. **`SCHEMA_VERSION` stays `"2"`** - the reworked brief's conditional ("stays
   `\"2\"` provided json instance records are byte-identical") is met: both new
   `TabCoverage` members are `omit_if_default`, and the json proof test passes.
   The debate (section 5.4) had argued the same. So no schema bump, and C moves
   no instance key.
3. **Part A under `lines`** - `answers` is now populated there too (the
   unconditional rule); the reviewer's "stays `[]`" note describes the pre-fix
   state. Reversible if the reviewer intended the override only where the model
   claimed an answer.
4. **Brief's example label not reused** - the brief names the pinned label
   `Enforce Unique Policy Numbers` but also says "synthetic text of your own; do
   not reuse any client wording". Since the string looks like the client's, we
   used our own (`Locked Rollup Count`).
5. **Part D reproduced N1 and is fixed** - the debate's falsifier was run: a
   `text L=<label> A=<answer>` reply on a mark-first row gave `value_raw is None`
   with `AMBIGUOUS_MARK` and `answers == [answer]` (N1), so the TEXT-only guard
   was applied (skip the geometric path for a `ControlType.TEXT` draft). The
   reworked brief now asks for exactly this. One reading note: "a mark inside
   the answer cell" is pinned twice - the answer cell holding only the mark
   (`value_raw is None`, unchanged) and the mark embedded in the answer cell's
   text (the rest binds, as for a markless text row); both are inert.
6. **Test pins moved (justified by `PIPELINE_VERSION` or a pinned `answers`).**
   Re-pinned: `JSON_RECORD_SHA256`/`LINES_RECORD_SHA256` in
   `tests/test_060_prompt_variants.py` (json moves on `pipeline_version` alone;
   lines also carries C's `model_declined`, a lines-only byte; the `PRE_K1` proof
   substitutes `pipeline_version` back and, for lines only, drops that member -
   it no longer substitutes `schema_version`); `SINGLE_MARK_STACKED_JSON` and
   `BETWEEN_CONVENTION_JSON` in `tests/test_t8_multimarker.py` (their only moved
   member is `answers`); the `PIPELINE_VERSION` literal in
   `test_060_prompt_variants.py` and `test_label_not_option.py`. The
   `SCHEMA_VERSION` literals reverted to `"2"`. No gold file, no `tools/` file,
   no prompt and no `rows.py` was edited; the gold scorer and the content-hash
   tests are green.
7. **`compute_coverage` disposition count semantics** - "rows" counted as
   distinct lattice rows across the tab's disposition records; a record with no
   resolvable row contributes 0. Only `model_declined` is asserted in tests, so
   the count's exact definition is a documented choice.
