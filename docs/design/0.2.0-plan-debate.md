# 0.2.0 plan: outcome of the Claude / hearth design debate

Goal: decide how to answer the nine findings (F1-F9) an integrator
reported after running form-extract 0.1.0 live on a real 17-tab
compliance-checklist workbook with an LLM at temperature 0, and fix the
release slicing, cache contract, provenance model and checkbox policy
before any code is written.

This is the outcome of a design discussion between Claude and hearth's
model (session `s561fdd06` in this project's `.hearth/sessions/`), not a
transcript. Four rounds were run. hearth read the code during the
discussion; all file:line citations below are hearth's or the reviewer's
and refer to the 0.1.0 tree. No file was modified and no real workbook
content was shared: the sample is described only by structure (tab counts,
merged-range counts, marker-neighbour classes). No real or employer data
appears here; names such as Table1 or "Label A" are invented.

## Verified facts the plan rests on

- `Pipeline.run` returns any stored instance keyed
  `<content hash>:<PIPELINE_VERSION>` (`pipeline.py:48`,
  `model.py:328-330`), including PARTIAL and FAILED ones. `save_instance`
  returns the existing record on a key collision and never overwrites
  (`store.py:98-101`). The key ignores model, params, prompt and
  `SCHEMA_VERSION` (imported at `pipeline.py:21`, only written to the
  record at `:140`).
- `author_drafts` has no per-chunk handling; a `ValueError`/`KeyError` from
  `parse_drafts` (`resolve.py:131,151`) escapes to `pipeline.py:104` and
  drops all drafts and the `calls` list (`:103-106`). Prompt and response
  bytes are already archived (`store.py:154-155`), but `archive_llm_call`
  is write-only (`store.py:139-166`).
- `Field` has no tab, element ids, field id or section path. The prompt
  projection prints text only (`resolve.py:70,79`).
  `region_id` is positional, `p{page}:c{col}:r{n}` (`layout.py:172`).
- `Option.selected` comes from the model; `_norm_bool_check` returns
  `"false"` when options exist and none matched (`schema.py:46`);
  `drafts_to_fields` falls back to `draft.answers` when nothing is
  selected (`resolve.py:224-227`). There is no non-answer-column concept
  anywhere in `layout.py`/`resolve.py`.
- `xlsx.py:81-82` ignores `sheet_state`, so hidden sheets are read as
  ordinary tabs.
- `harness._score_fields` keys on label/canonical (`harness.py:80-96`) and
  never looks at `Option.selected`, so checkbox behaviour is currently
  unmeasured and label collisions collapse in the scorer too.
- Structural census of the anonymised sample (aggregate only): 17 tabs
  (4 hidden); six tabs have identical geometry and identical label text; of
  32 `X` markers on the main tab, 22 sit between two option cells, 5 have
  only a right neighbour, 5 sit two columns from a left neighbour. The
  marker is therefore not nearest-option decidable and two conventions
  coexist on one sheet.

## Agreed plan

Slicing changed from the reviewer's opening proposal (A/B/C all in 0.2.0,
or B alone as the schema bump). Final cut:

| Release | Content | Output change |
|---|---|---|
| 0.2.0 | A1: reliability (F1, F2, F7) | none |
| 0.3.0 | A2 (honest checkbox states, non-answer columns) + B (provenance, F3/F4/F5, hidden-tab flag, `[pdf]` extra) | yes, deliberate; one schema bump, one golden re-pin |
| 0.4.0 | C: layout-signature reuse (F6), declared checkbox conventions | no new nulls beyond 0.3.0 |

Rationale for not stacking B on A1: a schema bump on top of a new cache key
removes any clean bisect point, and one bad key would invalidate the whole
release and re-spend all 17 tabs. Rationale for merging A2 with B: a null
checkbox is only usable if it carries a review flag and a stable field id,
and F3 (per-tab collapse) is an identity problem, so B is the headline fix
for the integrator.

### 0.2.0 (A1): reliability

Changes:

1. Cache key becomes a hash of the parts, not a concatenation:
   `sha256(content_hash | PIPELINE_VERSION | SCHEMA_VERSION | PROMPT_VERSION
   | model_or_"none" | sha256(canonical params json))`. `PROMPT_VERSION` is a
   new constant beside `BINDING_OUTPUT_CONTRACT`/`build_prompt`
   (`resolve.py:29,88`); it is telemetry, since the per-call key already
   hashes the literal prompt. `params` (notably temperature,
   `pipeline.py:30`) must be in the key. `model_or_"none"` separates
   perception-only runs from LLM runs (closes the "PARTIAL perception run
   replayed to a model run" case).
2. A hit requires `status == COMPLETE` (and no chunk errors). It is not
   "COMPLETE with fields": a genuinely empty sheet is legitimately COMPLETE
   (`pipeline.py:108-115` already downgrades no-fields-with-hypotheses to
   PARTIAL) and must not be re-spent forever.
3. Non-COMPLETE records bypass the cache. `Store.record_run(record)` writes
   them to `runs/<content_hash>/<run_id>.json`; `save_instance` and the
   index see only COMPLETE records. Invariant to test: the instance index
   contains only COMPLETE records. `Pipeline.run(path, force=True)` bypasses
   a COMPLETE hit.
4. Existing 0.1 instances stay on disk and are harmless: no new key equals
   an old `hash:1` key, and `_decode` drops unknown keys and rebuilds from
   present ones (`model.py:398-402`). Hard rule for later releases: every
   new `Field`/record attribute has a default, otherwise `tp(**kwargs)`
   raises and even reading history breaks. Code must not iterate the index
   expecting current-format keys.
5. Per-chunk isolation with three boundaries:
   - Transport (client): JSON mode (`response_format: json_object`) is a
     request concern passed through `params`; retry network/5xx/timeout up
     to 3 attempts with backoff. The `LLMClient` contract is documented
     as returning a JSON string.
   - Parse/repair (resolve): `_extract_json` + `json.loads`
     (`resolve.py:113-123`); on failure one repair attempt that appends the
     parse error. So at most 2 completions per chunk for parse problems.
   - Schema/per-field (pipeline/resolve): a bad enum or missing key drops
     that field only, keeps the chunk's good fields, and records
     `(chunk_id, tab, reason)`. No whole-chunk re-call for one bad field.
   - Run-level call budget so retries cannot silently double 17 calls to 34.
   The record is PARTIAL with a per-chunk error list; `LLMCall` metadata is
   preserved even on failure.
6. Per-call archive gains a read path: composite key
   `sha256(prompt_hash | model | params | purpose)` at
   `llm/calls/<key>.json`, one file per key (the store's
   `_write_json` is read-modify-write, `store.py:41-43,96-107`, and would
   race under concurrency). A re-run after a partial failure re-spends only
   the failed chunks. hearth's framing, adopted: the instance cache is per
   file and cannot give per-tab or incremental reuse; the per-call archive
   is the incremental mechanism.
7. Determinism if calls later run concurrently: collect results into a map
   keyed by chunk index and flatten in index order, never completion
   order (chunk order is already deterministic, `resolve.py:61-81`);
   `draft_id` is `uuid4()` (`resolve.py:150`) and stays run-local, never
   used as a sort key or embedded in reproducible output.

Exit criteria and tests (names are proposals):

- `test_failed_run_not_replayed`, `test_partial_run_not_replayed`: a
  FAILED/PARTIAL stored attempt re-executes on the next run.
- `test_perception_only_then_model`: a perception-only run is not served to
  a model run.
- `test_key_varies_with_model_prompt_params_schema`: each input changes the
  key.
- `test_force_bypasses_complete_hit`.
- `test_stored_v1_instance_never_served_for_v2_key`.
- `test_index_contains_only_complete`.
- `test_one_bad_chunk_keeps_others`: malformed reply on chunk 3 of 5 keeps
  chunks 1,2,4,5, one error naming chunk id and tab, status PARTIAL.
- `test_bad_field_keeps_chunk`: invalid enum on one field keeps the rest.
- `test_json_retry_then_success`, `test_retry_budget_enforced`.
- `test_rerun_after_partial_reuses_archived_calls`: only failed chunks hit
  the model (counted by a fake client).
- `test_empty_sheet_complete_is_cached`.
- Existing golden unchanged.

### 0.3.0 (A2 + B): honest checkbox states, provenance, identity

A2, checkbox honesty (output changes, so a changelog line is required):

- Unmarked option control becomes `None` (unanswered), never `"false"`:
  remove the fabrication at `schema.py:46`. The 0.2 golden does not exercise
  that path, so this part is golden-free.
- Marker classification, resolver-owned (geometry, not model): classify each
  marker as right-only / between / left-neighbour-only / unattached. This
  is cheap geometry; conventions are the 0.4.0 work, not the classes.
- Right-only auto-select without any convention, only under the
  conjunction: same band (`tol_y`, `layout.py:95,117`), marker's region is a
  FIELD_ROW (`layout.py:238`), candidate is option-like (non-empty, not a
  mark `_MARKS` at `layout.py:188`, not a bare number/date), exactly one
  candidate with nothing between and no other option in the grouping
  window, and not in a declared non-answer column. Any live competitor means
  AMBIGUOUS.
- `between` markers with no declared convention: `Option.selected = None`,
  `review_flag = True`, `ReviewReason.AMBIGUOUS_MARK` (`model.py:45,153-154`),
  and a defaulted `Field.ambiguity` record (marker element id, candidate
  element ids, reason). The model's per-marker value is discarded.
- The `draft.answers` fallback (`resolve.py:224-227`) must also be cleared or
  vetoed for ambiguous fields, otherwise a nulled `selected` regenerates
  `"false"` one layer down. This is a second load-bearing change and needs
  its own test.
- `non_answer_columns` ships here, not later, because the uniqueness rule's
  safety condition depends on it (a stray `X` in a tag/notes column is
  otherwise indistinguishable from a selection). Caller-supplied, never
  inferred; projected to the model as annotations only.

B, provenance:

- New defaulted fields: `Field.tab`, `Field.source_elements`,
  `Field.field_id`, `Field.section_path`, `SourceInfo` sheet state.
  `SCHEMA_VERSION` bumps; old records still load because every new
  attribute has a default.
- Element ids from the model without token inflation: the prompt does not
  number elements and should not emit 12-hex ids. The model returns
  `(region_id, band_id, segment_index)` and the resolver maps locally via
  the already deterministic band/segment order (`layout.py:123,408`). If
  segment counting proves unreliable, print a small integer prefix per
  segment (`- band 7: 0=... 1=...`). Unresolvable references are recorded
  as unknown with a reason, never guessed.
- `field_id` inputs: page index, column, region, normalised anchor text,
  ordinal within region. Excluded: `draft_id`, bbox, tab name, whole-row
  text. `region_id` becomes content-derived
  (`p{page}:c{col}:{type}:{first_anchor_norm}`, disambiguator only on
  collision). Documented guarantees: same file + same pipeline version gives
  identical ids; renaming a tab does not change ids; editing a label
  retires that field's id while neighbours keep theirs; ids are NOT stable
  across tab reorder (a reorder is a different placement) and, until the
  `region_id` change lands, not across row insertion above.
- `section_path` from enclosing header regions (the 7 regions layout already
  finds).
- Hidden sheets: capture `sheet_state`, exclude hidden tabs from default
  field output (the policy of skip vs flag vs keep remains an owner
  decision, but silently treating them as visible cannot ship).
- Harness moves to `field_id`, and gains `mark_selection_accuracy` and
  `silent_selection_rate`.
- `pymupdf` becomes the `[pdf]` extra (see below).

Exit criteria and tests:

- `test_repeated_tabs_distinct_fields`: six identical synthetic tabs give
  six distinct fields with correct `Field.tab`.
- `test_repeated_label_same_tab_distinct_ids`.
- `test_field_id_stable_across_reruns`, `test_field_id_survives_tab_rename`,
  `test_label_edit_retires_only_that_id`.
- `test_section_path_from_header_region`.
- `test_unresolvable_element_id_recorded_unknown`.
- `test_v01_record_loads_with_defaults`.
- `test_hidden_sheet_flagged_and_excluded`.
- `test_unmarked_option_is_none`, `test_between_marker_ambiguous_with_candidates`,
  `test_ambiguous_answers_not_regenerated_as_false`.
- `test_right_only_unique_selects`, `test_x_in_non_answer_column_ignored`,
  `test_x_leading_next_row_group_declines` (the uniqueness rule needs
  fixtures proving it declines; a rule with no declining fixture re-ships
  the F8 bug).
- Golden re-pinned deliberately: `ships_to_canada` and `vendor_status`
  (both between-marked) flip from a value to null, and the golden keeps
  exactly one positive checkbox assertion (`order_log`, X plus a single
  option, auto-selected) so it cannot pass by nulling everything.
- Local-private structure-only check reports integers only (see
  "Measure before F8 ships").

### 0.4.0 (C): reuse and conventions

- Layout-signature reuse (F6), per workbook, in memory only.
  The signature hashes geometry only: per tab, ordered
  `(column, region type, band count, quantised region bbox, per-band element
  count + quantised bbox, gap to previous band)`, quantised at the banding
  scale (`0.6 * median height`, `layout.py:95`), excluding `region_id` and all
  text. Reuse skips authoring, never resolution: values are always re-read
  from the current tab, which is what makes replay of someone else's filled
  answers impossible (`resolve.py:2` already draws this line).
  Verification ladder per tab: (1) geometry signature equal; (2)
  normalised anchor-label multiset equal; (3) every reused binding's
  address (`model.py:185-189`) resolves to a live element in this tab, any
  miss discards reuse for the whole tab and falls back to a fresh call; (4)
  reused fields carry `ProvenanceSource.REPLAY` (`model.py:30`) and anything
  short of fully clean sets `review_flag`.
  Shared strings across tabs (158 here) are not a license to reuse; only
  steps 1+2 together authorise it, and no similarity heuristic is built.
- Declared checkbox convention (API shape):
  `checkbox_conventions: list[{tab: str|glob, anchor_pattern: regex|None,
  convention: "mark_precedes_option" | "mark_follows_option"}]` in
  `PipelineConfig`. Selector is tab plus anchor-text regex, not `region_id`
  (positional until B). Only the `between` class needs a convention.
- The model may emit one advisory bit per region (do marks precede or
  follow options). It is applied only when it agrees with the geometric
  class; on disagreement or ambiguity it sets `review_flag` and selects
  nothing. Nothing model-drafted is auto-applied.
- Tests: `test_six_identical_tabs_share_one_binding` (call count 17 becomes
  fewer on a synthetic 6-identical-tab workbook), `test_same_geometry_different_labels_no_reuse`,
  `test_reuse_miss_falls_back_per_tab`, `test_adjacent_equidistant_marker_ambiguous_without_convention`,
  `test_declared_convention_selects`, `test_convention_disagreement_flags`.

## Measure before F8's convention logic ships

Synthetic goldens: one fixture per class (between, right-only, competitor,
notes-column X). Metrics: `mark_selection_accuracy` on decidable cases is
1.0 and `silent_selection_rate` (a selection made where the case is
ambiguous) is 0. That zero is the ship gate. The harness needs these
metrics first, because today it never reads `Option.selected`.

Local-private structure-only check on the real workbook, in the git-ignored
`local-private/` harness, reporting integers only: markers per geometric
class, ambiguous count, auto-selected count, review-flag count, per-tab
region counts, hidden-tab count. No labels, answers, element text or
bboxes. Gate: counts reconcile with the census (32 markers into 22 / 5 / 5)
and every marker lands in exactly one bucket.

Evidence required before ever promoting a default for `between`: a labelled
sample of at least 30 markers per form family with the convention constant
and zero cross-convention cases. The census (5 of 32 using the opposite
convention on the same sheet) fails that bar, so no default ships.

## pymupdf as an optional extra (F9)

- Lands in 0.3.0, as `form-extract[pdf]`; `dev` extra gains pymupdf.
- What breaks today: `pdf_text.py:8` imports pymupdf at module top and
  `ingest/__init__.py:8` imports `pdf_text`, so even the xlsx path pulls
  it in; `evals/synthetic.py:7` imports it; `tests/conftest.py` builds a PDF
  fixture used by `test_ingest.py`. Fixes: lazy imports inside functions
  (pattern already used at `ingest/__init__.py:48`); `probe_text_layer`
  (`pdf_text.py:13`) raises a typed "install form-extract[pdf]" error; the
  eval harness (`harness.py:164-170`) skips the PDF item with a reported
  reason when the extra is absent.
- Versioning: a base install that used to read `.pdf` now errors, which is
  breaking for PDF callers. Acceptable in 0.x; the changelog says
  "breaking" explicitly.
- Wording: README install section split into xlsx-only and `pip install
  "form-extract[pdf]"`; the NOTICE/releasing note on PyMuPDF/AGPL-3.0 stays
  and adds "optional extra, not installed by default". The PDF path stays
  labelled experimental until a live PDF run exists.

## Explicitly out of 0.2.0 (and 0.3.0)

Cross-file template registry (the per-workbook signature map is enough for
a 295 s one-workbook problem), concurrency itself (only the ordering rule
is fixed now), live PDF validation, similarity heuristics over shared
strings, auto-applying a model-drafted convention, and any hidden-tab
policy beyond flag-and-exclude-by-default.

## Risks

- 0.3.0 will look emptier than 0.1.0 on the real workbook (roughly 22 of
  32 markers become null). That is correct and will be read as a
  regression; the changelog must say the previous values were guesses.
- A key built from many parts means a mistake in canonicalising `params`
  silently causes cache misses (cost, not correctness); test with
  reordered-dict params.
- `field_id` is not stable across tab reorder or row insertion above until
  `region_id` is content-derived; this must be documented, not hidden.
- Retries without the per-call read path double spend; the budget and the
  archive read path ship together or not at all.
- The uniqueness rule is only as safe as its declining fixtures; value
  accuracy on the real sample (215 of 298 located values found in their
  row) is still unestablished and is not addressed by this plan.
- The `draft.answers` fallback can undo the F8 fix if left in place.

## Open questions for the owner (recommendation each)

1. Release slicing: 0.2.0 = reliability only, 0.3.0 = checkbox honesty +
   provenance, 0.4.0 = reuse + conventions? Recommend yes.
2. Hidden-tab policy: skip entirely, extract but flag, or extract as normal?
   Recommend flag and exclude from default output, with an option to
   include.
3. Is an unmarked option control "unanswered" (None) rather than "No"?
   Recommend None everywhere unless a form states a negative-by-default rule
   (nothing in the repo asserts one).
4. Accept 0.3.0's visible drop in populated checkbox values for `between`
   markers until a convention is declared? Recommend yes, with the changelog
   wording above.
5. Where does the caller supply `non_answer_columns` and
   `checkbox_conventions`: `PipelineConfig` fields, a sidecar YAML, or both?
   Recommend `PipelineConfig` first (typed), a loader for a sidecar later.
6. Is `[pdf]` breaking acceptable in 0.3.0, or should it be deprecated
   first (warn for a release, then move)? Recommend move in 0.3.0 with a
   clear error message, since the PDF path is untested live.
7. Should stored 0.1 instances be migrated or just ignored? Recommend
   ignored (kept on disk, never served); no migration tool.
8. Bounded run-log retention: keep forever, or rotate? Recommend leave
   unrotated in 0.2.0, document the directory so it can be deleted.

## What hearth disagreed with and why

- Hearth rejected the P2 cache design as stated: "failures stay on disk,
  never replayed" and "a later success caches under the same key" cannot
  both hold under `save_instance`'s never-overwrite rule. Adopted: route
  non-COMPLETE to a run log. Hearth also rejected the reviewer's
  `.failed-<n>` alternative as run_id-suffixing in a worse namespace.
- Hearth argued the hit predicate should be `status == COMPLETE`, not
  "COMPLETE with fields", because a genuinely empty sheet would be
  re-spent forever. Adopted.
- Hearth moved `SCHEMA_VERSION` and `params` into the cache key, and part of
  F8 into the first checkbox-related increment (the false fabrication at
  `schema.py:46`). Adopted.
- Hearth said "validation in the pipeline, not the client" was too coarse
  and split it into transport / parse-repair / per-field. Adopted.
- Hearth initially argued the census table should drive `selected`
  deterministically; the reviewer countered that 22 of 32 markers are
  equidistant. Converged: only the unique right-only class auto-selects;
  `between` stays ambiguous without a declared convention.
- Hearth proposed excepting an "unmarked Yes|No pair means No" case from
  nulling. On checking the fixture it withdrew: the golden's `"false"`
  comes from a canned stub (`canned.py:21`, mapped by `schema.py:31-34`),
  not from the fabrication path, so the golden is evidence of current
  behaviour, not of intent. Adopted: `None` everywhere.
- Hearth wanted B and C in separate later releases and A2 in 0.2.0; the
  reviewer wanted provenance earlier because F3 is the integrator's
  headline. Converged on 0.2.0 = A1 only, 0.3.0 = A2 + B.
- Hearth insisted `non_answer_columns` must not be split from auto-select
  (otherwise the F8 bug ships in a new form). Adopted; both land in 0.3.0.
- Hearth insisted hidden sheets cannot be ignored, because they inflate
  the F3 collapse counts. Adopted into B.

### Remaining dissent and unconfirmed points

- No material unresolved disagreement. Hearth's caveat: if the owner prefers
  A2 purely subtractive, auto-select must move to 0.4.0 together with
  `non_answer_columns`; shipping one without the other is not acceptable to
  it, and the reviewer agrees.
- Unconfirmed: the mechanism behind F3's "0 fields attributed to three
  repeated tabs" is not derivable from code alone. B's exit criterion
  claims the per-tab collapse is an identity problem; confirm the
  mechanism (tab-mapping by first element) against the integrator's run
  before the claim goes into release notes.

## Correction (2026-10-05): the 22/5/5 census

The original census above counted a field's own label as an option-like
candidate to the left of a marker. That was wrong: `Label | X | Option` is a
single checkbox whose box precedes its option, not a marker between two
options. The corrected integers for the 32 `X` markers on the main tab are 18
genuine between-markers (`Opt1 X Opt2`), 9 label-left single checkboxes
(`Label | X | Option`), and 5 markers with no left neighbour (`X | Option`).

The debate's conclusions still stand: there is no default for between-markers,
and a convention is declared per tab/anchor pattern. But the "roughly two
thirds of markers become null" estimate was too high — about 18 of 32 are
genuinely ambiguous and stay null until a convention is declared; the 9
single-checkbox rows were over-nulled and are corrected in 0.3.1.
