## The rule (decided; do not widen)

Applied once per field **at the `BindingDraft` stage, before resolution**, because resolution
branches on `draft.control_type is ControlType.TEXT` (`resolve.py` around lines 2079, 2202, 2225); a
post-hoc relabel of a finished `Field` would leave the typed value as a selected option and no answer.

A draft is **re-derived** when ALL of:

1. its stated `control_type` is `single_select`, and
2. it has **exactly one** option element (the count the replay measured: `len(options) == 1`), and
3. **no other draft on the same tab has a source element in any lattice row that this draft's source
   elements occupy** (the shared-row exception: a one-option control beside another control group is a
   side-by-side layout, not a typed value). Use the lattice the pipeline already builds (`rows.py`
   `row_of_element`); do not build a second row notion.

Then:

- If the draft's row (any lattice row of its source elements) holds a **marker** the layout classified
  (`layout.marker_classes`, the same vocabulary `_injected_marker_refs` uses; reuse `layout.py`'s own
  mark tokens, do not invent a glyph list), re-derive as **`bool`** and let the existing `bool` path
  resolve it.
- Otherwise re-derive as **`text`**: the cited option cell becomes the answer evidence
  (`answer_refs` / `answers` per contract, the same shape the model would have produced by writing
  `text L=... A=<that cell>`), and the option list is emptied. `source_elements` keeps every cell the
  model cited, so the scorer's identity (label + option cells) is unchanged, which is why the replay
  numbers transfer.

It does **not** touch `multi_select`, `bool` or `text` as stated, a `single_select` with 0 or 2+
options, or any draft failing condition 3. It reads no cell text and no wording. It cannot fix
`text>bool` (4 in the dump), `text>multi` (5) or `bool>text` (1); those stay as measured.

## Appendix: the reviewer's scratch replay (reference only; reimplement as tools/replay_kind_rule.py, do not import)

This produced the table above. It flips `control_type` on the saved record dump and re-scores with the real scorer; it models the shared-row exception with the real row lattice and does **not** model the marker clause.

```python
import sys, json, copy, collections
sys.path.insert(0,"tools")
import score_gold as s
from formextract.ingest import ingest
from formextract.layout import analyze
from formextract.rows import build_rows
G=sys.argv[1]
gdoc=json.load(open(G+"/gold_dev.json")); dump=json.load(open(G+"/rec_fix2_r3.json"))
gold=s.Gold(gdoc)
lat={}
for tab in gdoc["tabs"]:
    els=ingest(G+f"/{tab}.xlsx").elements
    lat[tab]=build_rows(analyze(els),{e.element_id:e for e in els},page=0)
def tab_of(f): return s._tab_of(f)
def rows_of(f):
    t=tab_of(f); return {lat[t].row_of_element(e) for e in (f.get("source_elements") or []) if lat[t].row_of_element(e) is not None}
fields=dump["fields"]
def candidate(f): return f.get("control_type")=="single_select" and len(f.get("options") or [])==1
def shares_row(i):
    t=tab_of(fields[i]); mine=rows_of(fields[i])
    return any(j!=i and tab_of(fields[j])==t and (rows_of(fields[j])&mine) for j in range(len(fields)))
def score(d):
    p,st,un=s._predicted_fields(gold, s._extract_fields(d)); return s.score_document(gold,p,st,un,None)
def apply(pred_fn):
    d=copy.deepcopy(dump); n=0
    for i,f in enumerate(d["fields"]):
        if candidate(f) and pred_fn(i): f["control_type"]="text"; n+=1
    return d,n
variants={"none":lambda i:False,"v1 (always)":lambda i:True,"v2 (not when row shared)":lambda i:not shares_row(i)}
for name,fn in variants.items():
    d,n=apply(fn); r=score(d); o=r["overall"]
    pt={t:(v["matched"],v["gold_fields"]) for t,v in r["per_tag"].items() if t in("text_field","side_by_side","yes_no_row","no_glyph_answer","matrix","typed_value","gutter_column","label_two_cells")}
    print(f"{name:28} fired={n:2} matched={o['matched']} ik={o['matched_ignoring_kind']} conf={o['kind_confusions']} prec={o['precision']} rec={o['recall']}")
    print("    ",pt)
```

### 1. Does the `SCHEMA_VERSION` "stays 2" precedent hold for a field added to `Provenance`?  No.

`to_dict` / `to_json` (`formextract/model.py:564-585`) do not omit defaults: `_encode` walks
`dataclasses.fields(obj)` and emits **every** field, `None` values included, for every dataclass in
the tree. `Store.save_instance` / `record_run` (`formextract/store.py:135,152`) serialise a record as
`to_json(record)`, so this is the real record serialiser, not a test shim. Measured, not reasoned:

- Adding `stated_control_type: str | None = None` and `kind_rule: str | None = None` to `Provenance`
  and re-running `tests/test_060_prompt_variants.py::test_the_json_contract_and_the_lines_base_path_are_byte_identical_to_head`
  moves the canonical json dump from `e33bafd6bc3a4b1fe0f8a791dfe62bc0e1f13a6cd0a77317e1695e97a194b1a8`
  to `365dd8ff1f2cc2d2ad3a5a086fd572ad52283a855e7aa3831aa00e5e88779f1a`. So `kind_rule=False` does
  **not** give today's bytes either: the fields sit on the dataclass whether or not the rule fires.
  The `stated_control_type`-only-when-the-rule-fires requirement cannot be expressed by a defaulted
  dataclass field at all under this serialiser.
- The cited coverage-block precedent does not transfer. `InstanceRecord` gained
  `coverage`/`coverage_min_ratio` in T4 and **those changed a record's bytes too**; `SCHEMA_VERSION`
  stayed `"2"` only because no frozen byte test covered a record at that time. "`SCHEMA_VERSION` stays
  2" is true of an additive field and false of "serialises byte-identically"; the spec needs both at
  once and they cannot both hold for `Provenance`.

**Resolution built after the owner said continue (then reverted).** The byte-preserving route is to
make the serialiser itself omit a field while it equals its declared default, gated by per-field
metadata (`field(default=None, metadata={"omit_if_default": True})`), so no existing field is affected
and `_encode`'s output for every other field is unchanged. That works: with it, `SCHEMA_VERSION`
stays `"2"`, an unaffected record's bytes are exactly HEAD's, and the two `Provenance` keys appear
only on a re-derived field. It still cannot give "every record byte identical to today's", because
the spec's own *Versions* bullet bumps `PIPELINE_VERSION` `"4"` -> `"5"` and `pipeline_version` is a
field of every record (the `_canonical_record_sha` helper in that test pops the run ids but **not**
the version). With the version bump the two pinned record dumps move by exactly that one field:
`JSON_RECORD_SHA256` `e33bafd6...` -> `082c6144f3dc83c0899987ee2b955559d0b02a7da1fbe47c634e2977f19dede2` and
`LINES_RECORD_SHA256` `06710633...` -> `5429b585de1815bbbca8dee2a316839742eafec1a271574a37644c8db51d342e`.
So the spec's *Switch* bullet ("with it `False`, every record byte is identical to today's; assert it
against the current golden record hashes") and its *Versions* bullet are mutually exclusive. Taking
*Versions* (the honest cache-invalidation signal) means editing those two test constants; taking
*Switch* literally means never moving `PIPELINE_VERSION`, which would serve stale instances for the
default contract. `SCHEMA_VERSION` was **not** bumped either way.

### 2. The rule re-derives an answer-bearing one-option `single` — the case to report

The debate (`0.6.0-kind-confusion-debate.md` §4) justifies the rule by listing the shapes it must
spare: "`yes_no_row` cites 2 options, `side_by_side` cites 2, `no_glyph_answer` cites at least 2 ...

### 3. The unchecked-lone-checkbox question (read-only)

Does the layout classify an empty-box glyph as a marker? **Yes**, for the unicode box glyphs.
`_MARKS` (`formextract/layout.py:26-39`) maps the empty-box glyphs `□` (U+25A1) and `☐` (U+2610) to
`GlyphKind.BOX`; `_classify_glyphs` (`layout.py:230-237`) mints a `Glyph` for any element whose text
carries a mark token, and `_classify_markers` (`layout.py:281-421`) classifies every glyph in a
FIELD_ROW band (a box with no option candidate lands as `MarkerClass.UNATTACHED`). So a one-option
`single` whose cited cell is only an empty box (`□`/`☐`) **has a classified marker**, and the marker
clause re-derives it as `bool`, not `text` — no guard needed for the unicode glyph. The only shape
that is **not** a marker is a literal ASCII `"[ ]"` (not in `_MARKS`, so no glyph, no row marker); a
guard, if ever wanted, should key on that spelling, not on `GlyphKind.BOX`. No guard was added.

### 4. Converting the cited option cell into answer evidence (per contract)

Built, then reverted with the rest. The working shape: at the `BindingDraft` stage (before resolution,
which branches on `draft.control_type`) the draft's single option becomes `answers=[option.text]` and,
on the lines path, `answer_refs = the option cell's refs` (carried on a new defaulted, non-serialised
`BindingDraft.option_refs`, since a draft is not a record); both contracts go through one shared
`apply_kind_rule(drafts, layout=..., elements_by_id=..., non_answer_element_ids=...)` called from
`author_drafts`, so the rule is not duplicated. The `bool` branch only flips `control_type` and lets
the existing bool path select the mark.

### Resolved after the stop (owner said fix, not stop)

The owner reviewed the stop and asked for the failure fixed rather than reported. The read above
holds: the `cut_before_end` case is the amended rule (its marker clause) working as designed, not a
misfire, and A4's premise that the remaining failure was the answer-bearing matrix shape is wrong
for it. The rule *must* fire here by the same clause the spec's own
`test_060_kind_rule.py::test_the_marker_clause_rederives_bool` asserts (a lone `single` whose one
option cell sits on a row with its classified `RIGHT_ONLY` marker). The only spec-legal fix is
therefore to re-pin the measurement, not to add a fourth condition (`Do not`, and A4's own
"the three conditions are the design").

`LINE_MUTATION_DELTAS["cut_before_end"]` is a *measurement* - the table's own comment says "regenerate
by rerunning this file" - not one of the frozen v2/v3 gold tables the `Do not` section names, so
re-pinning it is in bounds. It moves `selected_ok` -8 -> -9, `selected_total` -12 -> -13,
`selected_ambiguous_expected` -1 -> -2, `matched`/`label_*`/`options_*` -16 -> -17, `precision_num`/
`recall_num` -16 -> -17, and adds `kind_confusions` 1 and `spurious` 1.

Proven, not pasted: a new test (`test_the_extra_cut_before_end_delta_is_the_kind_rule`) runs the cut
mutation and the perfect run through the switch. With `kind_rule=False` the cut delta equals the
pre-K1 numbers exactly (`-8` / `-12`, no confusion) and the perfect overall equals the rule-on
baseline; with the rule on, the delta is the pre-K1 numbers plus the one marker-clause re-derivation.
No production code and no rule condition changed for this; only the pin and the proof test. Reran
`tests/test_060_lines_gold.py` alone: 55 passed.
