# 0.6.0 kind rule (K1): re-derive a one-option `single` as `text` (or `bool`) in the resolver

Status: spec for one build turn. Author: reviewer session, 2026-10-08. Builder: hearth.
Owner decisions this rests on (`0.6.0-kind-confusion-debate.md` sections 11 and 13): a resolver-side
kind override may exist in principle (yes), it fires on **both contracts** (yes), and the ship gate in
that doc's section 6 stands (acceptable). Start after the v4 matrix gold build has landed, so the two
builds do not both edit `tools/make_gold.py`-adjacent tests at once (this spec does not edit
`make_gold.py`).

## Evidence (offline replay of saved dumps; no provider call)

On a dev run of the lines contract (`fix2`, gemini-3.5-flash-lite, 16 tabs) 20 of 244 gold fields have
the wrong kind, and 10 of those 20 are gold `text` predicted `single_select` with **exactly one option
element** (the typed value cited as an option). Applying the rule below to that dump:

| rule | matched | kind confusions | precision / recall | `side_by_side` | `text_field` |
|---|---|---|---|---|---|
| none | 170 | 20 | 0.80 / 0.84 | 22/22 | 0/12 |
| v1: every one-option `single` -> `text` | 178 | 12 | 0.84 / 0.88 | **20/22** | 10/12 |
| **v2: v1, except when another field shares a lattice row with it** | **180** | **10** | **0.85 / 0.89** | **22/22** | **10/12** |

v1 breaks two `expected_ambiguous` `side_by_side` controls that have one option each. On two older
`base` dumps v2 changes nothing (154 -> 154, 118 -> 118) and v1 costs 2 each time. v2 fired on 29
fields in the `fix2` dump: 10 are gold `text`, 19 match no gold field (invisible to the scorer, real
in production). The scratch replay is `rule_probe.py`-style: reproduce it as the acceptance check
below, do not trust this table.

## The rule (decided; do not widen)

Applied once per field **at the `BindingDraft` stage, before resolution**, because resolution
branches on `draft.control_type is ControlType.TEXT` (`resolve.py` around lines 2079, 2202, 2225); a
post-hoc relabel of a finished `Field` would leave the typed value as a selected option and no answer.

A draft is **re-derived** when ALL of:

1. its stated `control_type` is `single_select`, and
2. it has **exactly one** option element (the count the replay measured: `len(options) == 1`), and
3. **no other draft on the same tab has a source element in any lattice row that this draft's source
   elements occupy** (the shared-row exception: a one-option control beside another control group is a
   side-by-side layout, not a typed value). Use the lattice the pipeline already builds (`rows.py`
   `row_of_element`); do not build a second row notion.

Then:

- If the draft's row (any lattice row of its source elements) holds a **marker** the layout classified
  (`layout.marker_classes`, the same vocabulary `_injected_marker_refs` uses; reuse `layout.py`'s own
  mark tokens, do not invent a glyph list), re-derive as **`bool`** and let the existing `bool` path
  resolve it.
- Otherwise re-derive as **`text`**: the cited option cell becomes the answer evidence
  (`answer_refs` / `answers` per contract, the same shape the model would have produced by writing
  `text L=... A=<that cell>`), and the option list is emptied. `source_elements` keeps every cell the
  model cited, so the scorer's identity (label + option cells) is unchanged, which is why the replay
  numbers transfer.

It does **not** touch `multi_select`, `bool` or `text` as stated, a `single_select` with 0 or 2+
options, or any draft failing condition 3. It reads no cell text and no wording. It cannot fix
`text>bool` (4 in the dump), `text>multi` (5) or `bool>text` (1); those stay as measured.

## Contracts, config, provenance, versions

- **Both contracts.** The json path (`_parse_one_draft`) and the lines path (the `BindingDraft` built
  around `resolve.py:931`) both call one shared function; do not duplicate the rule.
- **Switch.** `PipelineConfig.kind_rule: bool`, **default `True`** (the owner decided it fires on both
  contracts), part of the instance cache key. With it `False`, every record byte is identical to
  today's (assert it against the current golden record hashes in `tests/test_060_prompt_variants.py`).
- **Provenance.** Keep the model's stated kind. Add additive, defaulted fields to `Provenance`
  (`stated_control_type: str | None = None`, `kind_rule: str | None = None` naming the rule id
  `one_option_single`), written **only when the rule fires**, so an unaffected record serialises
  byte-identically. Follow the coverage-block precedent (`SCHEMA_VERSION` stays `"2"`); **verify**
  that precedent holds for a field added to an existing dataclass (check `to_dict` / the serialiser)
  and, if it does not, stop and report instead of bumping the schema.
- **Versions.** `PIPELINE_VERSION` `"4"` -> `"5"` (the instance key moves: output changed on the
  default contract too). The call cache keys on prompt text, which does not change, so cached calls
  are still served. Add a `KIND_RULE_VERSION = "1"` constant exported beside it.
- A re-derived field is not `review_flag`ged for that reason alone.

## Tests (hermetic; write expected values by hand from this spec first)

- The three conditions, each with its negative: a one-option `single` alone on its row -> `text`;
  two options -> unchanged; **shares a row with another field -> unchanged** (the `side_by_side` shape);
  stated `multi_select` / `text` / `bool` -> unchanged.
- The marker clause: a one-option `single` whose row holds a classified marker -> `bool`.
  **A lone checkbox is the case to think about**: a checked box with a marker -> `bool`; an
  *unchecked* lone box ("[ ] I agree") has no marker, so the rule would call it `text`. Determine from
  the layout whether an empty-box glyph is a classified marker. If it is not, **do not fire** when the
  one option cell's text is only a checkbox glyph, add that guard, and say so in the outcome note.
- Re-derived `text` resolves to the same `answers` as a draft that stated `text A=<cell>` (build both
  and compare).
- Both contracts: the same drafts through the json parse path and the lines path give the same
  re-derived result.
- `kind_rule=False` record bytes equal to today's; an unaffected record's bytes equal to today's even
  with the rule on; the affected record carries `stated_control_type`.
- Falsifiability: a mutation that drops condition 3 fails a test; one that applies the rule to
  `multi_select` fails a test.
- Replay acceptance (a tool, not a unit test): add `tools/replay_kind_rule.py` that takes a gold dir
  and a `--record-out` dump and prints the scorer's overall and per-tag counters with the rule off and
  on, reading the lattice from the gold `.xlsx`. It must reproduce the table above to the digit on the
  reviewer's dump; hearth has no dump, so test it on a synthetic dump built from the canned perfect
  response (rule changes nothing) and on that dump with one text field's control type swapped to
  `single_select` with one option (rule restores it).

## Appendix: the reviewer's scratch replay (reference only; reimplement as tools/replay_kind_rule.py, do not import)

This produced the table above. It flips `control_type` on the saved record dump and re-scores with the real scorer; it models the shared-row exception with the real row lattice and does **not** model the marker clause.

```python
import sys, json, copy, collections
sys.path.insert(0,"tools")
import score_gold as s
from formextract.ingest import ingest
from formextract.layout import analyze
from formextract.rows import build_rows
G=sys.argv[1]
gdoc=json.load(open(G+"/gold_dev.json")); dump=json.load(open(G+"/rec_fix2_r3.json"))
gold=s.Gold(gdoc)
lat={}
for tab in gdoc["tabs"]:
    els=ingest(G+f"/{tab}.xlsx").elements
    lat[tab]=build_rows(analyze(els),{e.element_id:e for e in els},page=0)
def tab_of(f): return s._tab_of(f)
def rows_of(f):
    t=tab_of(f); return {lat[t].row_of_element(e) for e in (f.get("source_elements") or []) if lat[t].row_of_element(e) is not None}
fields=dump["fields"]
def candidate(f): return f.get("control_type")=="single_select" and len(f.get("options") or [])==1
def shares_row(i):
    t=tab_of(fields[i]); mine=rows_of(fields[i])
    return any(j!=i and tab_of(fields[j])==t and (rows_of(fields[j])&mine) for j in range(len(fields)))
def score(d):
    p,st,un=s._predicted_fields(gold, s._extract_fields(d)); return s.score_document(gold,p,st,un,None)
def apply(pred_fn):
    d=copy.deepcopy(dump); n=0
    for i,f in enumerate(d["fields"]):
        if candidate(f) and pred_fn(i): f["control_type"]="text"; n+=1
    return d,n
variants={"none":lambda i:False,"v1 (always)":lambda i:True,"v2 (not when row shared)":lambda i:not shares_row(i)}
for name,fn in variants.items():
    d,n=apply(fn); r=score(d); o=r["overall"]
    pt={t:(v["matched"],v["gold_fields"]) for t,v in r["per_tag"].items() if t in("text_field","side_by_side","yes_no_row","no_glyph_answer","matrix","typed_value","gutter_column","label_two_cells")}
    print(f"{name:28} fired={n:2} matched={o['matched']} ik={o['matched_ignoring_kind']} conf={o['kind_confusions']} prec={o['precision']} rec={o['recall']}")
    print("    ",pt)
```
