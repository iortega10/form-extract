# 0.6.0 style cue (S1): show cell shading in the lines projection

Status: spec for one build turn. Author: reviewer session, 2026-10-08. Builder: hearth.

## Why

Live dev runs of the lines contract (gemini-3.5-flash-lite, `fix2`, 6 s paced) lose most of their
remaining score to **kind** confusion, not grouping: `text_field` is 12/12 grouped but 1/12 strictly
matched, `text>single` is 10 of the 13 `fix2` confusions, and `label_two_rows` reads a typed answer
beside a label as an option. The projection prints only cell text, so a typed answer
(`Bracket outer 227`) and an option (`Upper shim`) look identical. In the gold sets options are
bold **and filled** and typed answers are plain; `Element.fill` is ingested
(`formextract/ingest/xlsx.py:126`) but never reaches the prompt. `Element` has **no bold flag**.

## Scope (one turn)

1. A projection option `style_tags` (default **False**), the same kind of switch as `row_tags`
   (`resolve.py::_project_page_rows`, L3a). With it on, a segment whose element has a non-default
   fill is printed `k=text [shaded]`; every other byte of the line is unchanged, so `row.seg`
   coordinates mean the same thing with it on or off. It sits beside the existing `[annotation]`
   suffix; a cell that is both prints `[annotation] [shaded]`.
2. One new lines prompt variant, `fix2_style`: `fix2`'s text plus ONE added sentence defining
   `[shaded]` as "the cell has a fill colour; options and checkbox cells are often shaded, typed
   answers often are not; it is evidence, not a rule". The variant turns `style_tags` on. `base`,
   `fix1`, `fix2`, `fix2_notags` and the json contract stay **byte-identical** (assert it).
3. `style_tags` (or the variant name, whichever already feeds it) is part of the instance cache key
   and the call cache key. Check how `row_tags` / `prompt_variant` get there and do the same.

## Decisions already made (do not reopen)

- **Fill only.** Do not add a bold flag to `Element` or touch ingest: that changes the element
  schema and every cached record, and needs the owner's sign-off. Record "bold is not available" in
  the turn's outcome note.
- **What counts as shaded.** First find out, from `ingest/xlsx.py`, what an unfilled cell yields
  (`None`, `0`, or a white/theme value). Print `[shaded]` only for a real, non-default fill. Unit
  test the boundary with an unfilled cell, a solid fill, and a theme/indexed colour that
  `_argb_to_int` maps to `None`.
- **Do not change** `rows.py`, `layout.py`, the gold generator, the scorer, or any committed gold
  hash. `make_gold.py --gold-version 2` and the v3 hash tables must still pass untouched.
- No new dependency. Python 3.11 to 3.14. No network in tests.

## Risk to record (not to solve)

The cue is calibrated on **synthetic** gold where options are shaded. Real forms often shade the
*input* cells and leave option labels plain, which inverts the signal. That is why the sentence says
"evidence, not a rule", why the option defaults to off, and why this variant must not be promoted
to the default prompt on the strength of dev-gold numbers alone. State this in the CHANGELOG entry.

- With it on: shaded and unshaded cells, a shaded annotation cell, a merged shaded cell, and that

- Cache keys differ between `fix2` and `fix2_style` for the same workbook.

## Outcome (builder, this turn)

**What was changed.** `formextract/resolve.py` gains `style_tags` on
`_project_page_rows` and `project_lines_chunks` (default `False`), a private
`_is_shaded(element)` (`element.fill is not None and element.fill != 0`), the
`fix2_style` prompt (`_lines_prompt_fix2_style`, `_LINES_STYLE_SENTENCE`) and its
row in the registry, the new `LINES_VARIANT_STYLE_TAGS` map and its
`lines_variant_style_tags(variant)` accessor. `formextract/pipeline.py` passes
`style_tags=lines_variant_style_tags(self.config.prompt_variant)` into the lines
projection, and the `PipelineConfig.prompt_variant` docstring spells out both
projection options. No other module is touched: `rows.py`, `layout.py`,
`ingest/`, the gold generator and the scorer are untouched, and no committed gold
hash moves.

**The unfilled-cell value.** `ingest/xlsx.py` sets `fill=_argb_to_int(start_color)`:
- an unfilled cell yields **`0`** (openpyxl's default `00000000`),
- a solid `RRGGBB` (`FFEEDD`) yields its **integer** (`0xFFEEDD`),
- a theme colour (`Color(theme=6)`) yields **`None`** (`_argb_to_int` needs a 6/8-char
  `rgb` string), and a merged cell keeps the fill of its anchor cell.

So the default is `0` **or** `None`, and `_is_shaded` treats both as unshaded —
which is what the spec's "only a real, non-default fill" rule requires. Pinned in
`test_the_style_tag_marks_filled_cells_only`, which also checks the suffix on an
unshaded option, a shaded option, a theme-filled cell and a `[annotation]
[shaded]` cell, plus a merged shaded cell.

**Anything surprising.** `Element` has no bold flag (as the spec says), so the
gold's "bold **and** filled" cue can only be carried by fill; the sentence is
written so that a shaded *input* cell does not read as an option. Adding the
variant to the registry automatically extends `test_live_probe.py` (its gold-mode
loop iterates `probe.PROMPT_VARIANTS`), so `--prompt-variant fix2_style` is
covered by the existing parametrised test rather than a new one; a small
`test_live_probe_accepts_the_style_variant` names the case explicitly anyway.

**Tests.** `tests/test_060_prompt_variants.py` extended (28 tests in the module,
up from 20): a frozen `fix1`/`fix2`/`fix2_notags` prompt sha256 and a new pinned
`fix2_style` one, the "one inserted sentence" property, `style_tags=False` byte
identity across **both** gold sets (dev and held-out, 13 tabs) and the fixture
matrix, the shaded/unshaded/annotation/merged suffix checks with row and segment
numbering held fixed, the cache-key split between `fix2` and `fix2_style`, and the
probe acceptance. The closed-vocabulary, no-quote, no-gold-word, example-parse and
cache-key tests extend to the new variant. `MAX_PROMPT_CHAR_RATIO` moved `1.45 ->
1.60` (measured: `fix2_style` = 2705 chars, x1.530). `tests/test_live_probe.py`
needed no edit. Full suite: **522 passed** (`python -m pytest -q`, `OPENPYXL_LXML=False`),
changed file alone first.
