# 0.5.0 design note

0.5.0 is an output-cost and reliability increment; it does not change how
fields are resolved from a parsed response.

- **Smaller default prompts.** `PipelineConfig.include_address` defaults to
  `False`, so the prompt no longer asks for the per-field `address` object and
  no longer explains it. The `address` key is ignored if a model returns it
  anyway (`draft.address` stays `None`). Setting `include_address=True`
  restores the exact 0.4.0 prompt byte-for-byte. `PROMPT_VERSION` and
  `PIPELINE_VERSION` move to `3`, so cached 0.4.0 records are not served.
- **Failures are not indexed.** A model response is added to the LLM lookup
  cache only when it parses as JSON **and** every field inside it parses
  (`parse_drafts_with_errors` returns an empty field-error list). A response
  that parses but has a per-field error is archived with `index=False`: its
  prompt/response files and the run's `llm_calls` provenance are still written,
  only the lookup entry is withheld, so a rerun re-sends that chunk instead of
  being served the same partial answer. This holds for the original response and
  for a repair response. A 0.4.0-era unparseable cached entry is treated as a
  cache miss and the original prompt is re-sent rather than shortcut to the
  repair prompt.
- **Optional concurrent chunk resolution.** `PipelineConfig.chunk_workers`
  (1..32, default 1) authors projection chunks with a thread pool. Results are
  returned in chunk order and the call budget is taken under a lock. The
  `LLMClient` must be thread-safe when `chunk_workers > 1`.
- **Reuse works with concurrency.** Layout-signature reuse is restructured into
  three phases (key/exemplar selection, exemplar authoring, in-order replay or
  fallback). `chunk_workers=1` output is unchanged from 0.4.0.
- **Tab names after hidden sheets.** Page-to-tab mapping now comes from each
  page's element `sheet` (falling back to `ing.sheet_names[page]`), so a hidden
  sheet before a visible one no longer shifts every later tab name.
