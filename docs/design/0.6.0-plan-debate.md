# 0.6.0 plan: outcome of the Claude / hearth design debate

Goal: decide how 0.6.0 makes LLM extraction faster, cheaper and more
complete, before any code is written. The trigger is a live test of 0.5.0 on
one tab of a private anonymized workbook that showed (a) output volume, not
input and not our code, is the cost, (b) the same tab yields 1, 5, 62, 63 or
82 fields depending on the model while the record says `complete` with 0
errors every time, and (c) a provider 400 is retried three times.

Status: the outcome of a read-only design discussion, not a transcript. It
edits no source. It is the input to a build spec and to the owner's decisions.

Method. Claude (this file's author) read the code and wrote a position per
question *before* the debate (the opening message, so hearth did not lead),
then argued five live rounds with hearth-cli's model through `hearth --json`
(backing model: whatever the project resolves; not assumed), session
`s9afc291d` in `form-extract/.hearth/sessions/` (resume with
`--resume s9afc291d`). Hearth read the repo and cited `file:line`; Claude
re-verified the claims that carried weight (marked "verified" below) and found
hearth wrong three times (section 10). One `gate_paused` fired (round 4, a
mutating tool call, auto-denied; nothing changed). No network or API call was
made; no API key was available.

Privacy. The only data are the integers the owner's live test produced
(latencies, token counts, field counts, output-share percentages, anchor and
region counts). No label, sheet name or cell text appears here, and the
workbook is not in the repo.

## 0. Headline

1. **The biggest lever is configuration, not code.** The measured
   gemini-2.5-flash run with default thinking emitted 51.6k tokens (63
   fields); with thinking off, 19.7k tokens (82 fields). Roughly 32k tokens of
   reasoning dwarf every prompt or contract item combined. The highest-value
   0.6.0 deliverable is a ranked, cost-annotated levers table plus a probe that
   proves each row (T1, T3).
2. **0.6.0's code value is making the levers selectable and measurable**:
   a re-encoded output contract (T5), a coverage block that stops `complete`
   meaning "the model said so" (T4), truncation salvage (T2), and opt-in
   sub-tab chunking (T7). It is not a shorter prompt: input is ~4.1k tokens and
   ~1 s of our own time.
3. **The package currently cannot tell a good extraction from a 5-field one on
   a 98-anchor tab.** Existing `residuals` are a global substring test and
   under-report (section 2). Coverage is the instrument every later turn is
   measured with, so it lands before the contract and the chunker.
4. **"Split by region group" is wrong as stated.** Regions are per column; a
   region split separates the label column from the value columns. Chunking
   must cut by y-position across all columns (section 5).
5. **Near-match reuse is the second-biggest candidate for this workbook but is
   not a 0.6.0 feature.** Reuse never fires there (equal geometry, ~6% differing
   anchors). 0.6.0 only makes the near-miss visible (profiler integers).

Order rationale. T1, T2 are model-invisible and bisect cleanly. T3 before T5
because only a live probe can show a real model emits `R3:12.0`. T4 before
T5 and T7 because a contract or chunk change can silently lose fields and
coverage is how that is seen. T4's tie-break before T7 because chunking can
flip the ordering of two drafts sharing an anchor band (`_anchor_sort_key` has
no secondary key, `resolve.py:652-654`). T5 ships alone (no chunking, no
instruction) so its saving is attributable.

## 2. Verified facts the plan rests on

All cited against the 0.5.0 tree; "verified" = Claude re-read it, not only
hearth.

- **The 0.5.0 output contract** is `BINDING_OUTPUT_CONTRACT`
  (`resolve.py:47-54`); each ref is `{"region_id": str, "band_id": int,
  "segment_index": int}` (`:52`, parsed `:262-269`). Region ids are
  content-derived and long (`p{page}:c{col}:{type}:{first_anchor_norm}`,
  `layout.py:177-191`). Verified.
- **`source_elements` is load-bearing, not decoration.** The resolved element
  ids become `Field.source_elements` (`resolve.py:971, 1115`); marks are
  decided by intersecting them with `layout.glyphs` (`:729-740`); the anchor
  band for ordering is the ref whose `region_id == draft.region_id`
  (`:645-654`); replay re-points refs by `(column, band_id)` and re-reads TEXT
  values from them (`:544-578`, `reuse.py:62-74`); reuse validates every ref
  (`:620-642`). Verified.
- **`draft.region_id` is the anchor identity**: grouping bucket and ordinal
  (`resolve.py:921-934`), page/column for `_field_id` (`:657-661, 930-932`),
  `region_ref` and bbox (`:488-489, 1108`). It cannot be inferred as "region of
  the first ref": a label ref placed second would mis-group, mis-order and
  re-id a field with nothing detecting it. Verified.
- **`selected` is not freely droppable.** It is overridden only when a glyph
  decision exists (`resolve.py:984-1044`); on the no-glyph path the model's
  `selected` drives `value_raw` (`:1043-1054`) and the normalizers read it
  (`schema.py:26-55`). It is also the input to the `AMBIGUOUS_MARK`
  cross-check (`:1082-1088`).
- **`confidence`** reaches only `provenance.llm_confidence` (`:1065`); no
  decision reads it. Verified (grep).
- **Regions are per column**: one region = a run of same-type bands inside one
  column (`layout.py:194-227`); `region.band_ids` are that column's global band
  indices; `project_chunks` emits one chunk per page (`resolve.py:110-155`).
  Verified.
- **Anchors** come only from the single densest FIELD_ROW column
  (`layout.py:534-599`). They exclude GRID regions, which come from a separate
  hypothesis construction (`:498-530`). The prompt never shows hypotheses
  (`build_prompt`, `resolve.py:167-203`). Verified.
- **Existing `residuals` under-report**: one concatenated normalized blob of
  every field's label/option/answer/annotation/value text, and an element is
  "consumed" if its normalized text is a *substring* of the blob, globally, not
  per tab (`pipeline.py:613-632`). A short element such as "No" is consumed by
  any field containing "no". Verified.
- **Transport retries every exception** three times with backoff
  (`resolve.py:311-319`); there is no 4xx notion. The package ships no provider
  client, so the 400-x3 was this loop. The repair loop is *not* involved: a
  raised transport error returns before it (`:435-439`). (Hearth first claimed
  the repair loop also burned on a 400; it withdrew that.)
- **No `max_tokens`, `finish_reason` or usage handling exists** beyond the
  docstring (`resolve.py:89`) and `LLMResponse` fields (`:69-75`). A truncated
  response raises inside `_extract_json` (`:206-216`), goes to the repair call
  (`:441-459`), which re-sends the same prompt and truncates the same way: 2x
  spend, still PARTIAL. Verified.
- **PARTIAL runs re-read cached model responses**: instance-level caching
  excludes non-COMPLETE (`store.py:118-141`), but `find_llm_call` caches each
  response that parsed with no field errors (`resolve.py:367-382, 482`;
  README "Reading a result"). A `min_coverage` failure costs a recompute, not
  tokens, unless `force=True` or a field-level parse error. **Correction
  (2026-10-06):** "unless `force=True`" was the plan's own wrong belief (the
  same one behind the README pitfall) — `force=True` bypassed only the instance
  cache, so an unchanged prompt was still served from the call cache and spent
  0 tokens; T1b makes the code match the docs.
- **Reuse keys on the page**: `(page_geometry_signature, page_anchor_multiset)`
  with `page = chunk.page` (`pipeline.py:363-372`); every chunk of a page would
  share a key. Verified.
- **Cache key** is the hash of parts (`compute_cache_key`,
  `pipeline.py:229-267`); `find_instance` serves any COMPLETE, error-free
  record by that key (`store.py:118-126`). Any knob that changes status, prompt
  or output must be in it.
- **Replay copies `draft.label`** (`resolve.py:597-616`); a differing row would
  emit a wrong label with clean `REPLAY` provenance. This is why near-match
  reuse (replay with label differences) is not a cheap extension.

## 4. A found defect adjacent to completeness (T8)

Read from the code by both sides; **not executed**. `_geometric_mark_decision`
returns `auto_select` for `right_only[0]` only (`resolve.py:777-796`), and
`drafts_to_fields` then sets `selected = (o.text == matched)` for exactly one
option (`:1023-1032`), overwriting the model's other selections. A dense row
`X A  X B  X C` does not hit this (interior marks have a left candidate and
classify BETWEEN, `layout.py:405-406`; the first sees several right candidates,
COMPETING). It fires for a **vertically stacked** multi-select grouped by the
model into one field: each `X Option` is its own FIELD_ROW band, the
cross-band loop pairs only within `tol_y` (`layout.py:384`), so each marker is
RIGHT_ONLY with one candidate. Result: wrong value always; quiet about half the
time (flagged `AMBIGUOUS_MARK` only if the model also set `selected=True` on
the others, `resolve.py:1084-1088`). No test pins it
(`test_checkbox_states.py` cases are single-marker). It changes resolution
semantics and needs a stacked fixture and an eval diff, so it is a named
separate fix, T8.

## 5. Sub-tab chunking design (T7)

1. **Cut by y, never by region.** Build the union of band y-intervals over all
   columns of a page; candidate cuts are the gaps where no band in any column
   spans the line; choose the largest gaps nearest the target size. A gap that
   exists only in the label column would land inside a (taller) value band in
   another column and sever label from value in both halves
   (same-row pairing uses `abs(delta center_y) <= tol_y` and a height factor,
   `layout.py:475-478`).
2. **Owned anchors.** Each anchor belongs to exactly one chunk. Context-only
   lines (nearest HEADER region, a few rows above) are printed tagged so the
   model does not author them; a draft whose anchor band is outside the chunk's
   ownership is dropped. This prevents duplicate fields at cuts.
3. **Global ids.** Aliases and band ids are page-global; the chunk prints the
   global `- band {band_id}` and alias headers. Merge in chunk order; field
   order and `field_id` are independent of chunk order except for anchor-band
   ties, closed by T4.
4. **Fields spanning the cut.** Possible (a grid below its label across a
   cut). The cut prefers the largest vertical gap and a HEADER boundary; a
   residual risk, visible as unbound units in the coverage block.
5. **Cost.** Per chunk: re-sent prompt prefix plus context lines (~0.3-0.8k
   input tokens, estimate). Output total ~flat. Latency bounded by per-call
   floor `F`.
6. **Trigger.** `chunk_max_anchors: int | None = None`. When set and a tab has
   more anchors than the value it is split into `ceil(anchors / value)` chunks.
   In `compute_cache_key`. Coverage block shows `chunked`.
7. **Reuse.** Guarded: `ValueError` if both are set (section 3).

## 6. Completeness-signal design (T4)

### 6.1 The block

Per tab (a defaulted record field, e.g. `Record.coverage: list[TabCoverage]`):

- `tab` (name; already public on the record), `units_total` (anchor rows +
  GRID regions), `units_consumed`, `ratio` (`None` when `units_total == 0`),
  `anchors`, `grid_regions`, `chunked`, `max_anchors_per_tab`,
  `unbound`: list of `{region_id, band_id}` (no text, optional first element
  id), capped (e.g. 50) with `unbound_truncated: true` when the cap bites.
- Record level: `min_ratio` over eligible tabs.

### 6.2 Definitions and rules

- Denominator is perception (deterministic, model-free), the numerator is the
  model's resolved refs: no circularity.
- Anchor unit consumed iff any element of the anchor's own band in the anchor
  column is in some field's resolved `source_elements`. This is deliberately
  over-inclusive (a field citing an annotation element that lives in the label
  band counts the row), which errs toward fewer false alarms. Documented in
  the docstring.
- GRID unit consumed iff any element of any band of the region is. GRID
  regions cannot contain HEADER bands because regions group only consecutive
  same-type bands (`layout.py:207-227`); a test pins that invariant.
- `non_answer_columns`: a unit all of whose elements are non-answer ids is
  excluded; if the anchor column itself is non-answer, `units_total = 0` and the
  ratio is `None`.
- `ratio is None` is **ineligible**, never a failure, in `min_coverage` (per tab
  and in the record minimum). Tested.
- Status: unchanged by default. With `min_coverage = x`, each tab with
  `ratio < x` adds one short error (`tab <name>: row coverage 0.05 < 0.50`) and
  the run is `PARTIAL`. Detail stays in the block, not in `errors`.
- A rerun after a `min_coverage` failure re-reads cached responses (section
  2): it costs a recompute, not tokens, unless `force=True`.
- Threshold: none by default. Nothing in one file defends a number; the
  integrator chooses. The README may show a worked example, labelled as an
  example.
- What the integrator sees: `record.coverage`, per-tab ratio and the unbound
  handles to inspect, and `chunked`/`max_anchors_per_tab` pointing at the knob.
- Residuals: untouched (coarse text check); coverage answers "was this row
  used".

### 6.3 The T6 instruction (opt-in, default off)

Replace "One field per user-visible question" context with a single group
(hearth's wording, which avoids contradicting the `...All` bullet):

> A grid is one field only when a single control (e.g. "All") selects the whole
> of it; a block of label rows with no such control is one field per row. Every
> label row belongs to exactly one field, or, if it is an instruction or note,
> to the nearest field's annotations. Do not summarise or skip rows.

It will raise output (more fields), spending part of T5's saving on
completeness: with compact refs the per-field ref cost is ~5 tokens instead
of ~30 (estimate). Few-shot (150-300 input tokens) is held as T6c, only if the
sentence under-delivers, because it anchors a format while the contract is
still moving.

## 7. The live probe (T3)

`tools/live_probe.py`, opt-in, outside the package. Hermetic test: a stdlib
`http.server` on `127.0.0.1:0` in a thread with canned responses.

- Args: workbook path, `--provider {openai,gemini}` (`--base-url` makes the
  OpenAI provider reach any compatible endpoint, including a no-key local one:
  empty `--env-var` means no auth header), `--model`, `--env-var NAME`
  (provider default), repeatable `--param k=v` (coerced to int/float/bool/str),
  `--tab N` (index, never a name), `--repeat K`, `--contract {compact,legacy}`,
  `--instruction {on,off}` after T6, opt-in `--dump <path>`.
- Key: `os.environ[NAME]` only; never printed, logged, stored or placed in an
  exception (redact any substring equal to the key from `str(exc)`); Gemini
  auth by header, not `?key=`; never print a response body; `main` wrapped in a
  redacting handler.
- Does its own `ingest`, `analyze`, `project_chunks`, `build_prompt`; calls the
  provider directly (not through the store: no archive, so no prompt/response
  text on disk); parses with `parse_drafts_with_errors` and resolves in memory.
- Output is built from a fixed dict of numeric keys, so leaking text is
  impossible by construction: input chars, prompt tokens, output tokens,
  **reasoning/thought tokens separately** (`reasoning_tokens`,
  `thoughtsTokenCount`), `finish_reason` class and whether it equals the length
  cap, seconds, tok/s, fields, parse errors, truncation flag, unresolved refs,
  anchors, grid units, coverage numerator/denominator, status class. With
  `--repeat K`: min/median/max and a truncation count, not K rows.
- To separate rate from the per-call floor `F`, it supports a fixed tiny output
  run and a real-size run on the same model (slope = rate, intercept = F).
- `--dump` is the one path text can reach disk, by explicit request, with a
  warning, outside the store.
- Hermetic assertions: (a) stdout parses as a dict whose every value is
  `int`/`float`/`None`; (b) the key appears nowhere in stdout, stderr or any
  exception text; (c) a fake 401 whose body echoes the key yields an exception
  whose message does not contain it.
- Profiler addition (integers only, same `page_anchor_multiset` and
  `normalize_label` the pipeline uses): per equal-geometry tab pair the anchor
  symmetric-difference, intersection, union and total, plus
  `closest_pair_diff` and a `pairs_by_diff` histogram. Never anchor text.

## 8. Token and latency estimate (ESTIMATES, assumptions stated)

Inputs (measured, one tab): the 51.6k / 19.7k / 22.2k / 2.8k / 1.6k figures
are **output** tokens; the prompt is ~4.1k input tokens in every run. Output
shares of the 82-field response (49.7k chars): source_elements 53%,
options 12%, region_id 8%, label 6%, annotations 5%, control_type 4%, answer
3%, confidence 2%, `selected` ~4%.

**Output cut from T5 (estimate).** Per ref, the 0.5.0 object is ~90-110
characters (~30+ tokens, because underscored ids tokenise poorly) versus
~8 characters (~5 tokens) for `R3:12.0`; a 52-option grid collapses further
with a range. Characters: `53% x (0.85..0.90)` + (`8%` -> ~`1.5%`) + `2%`
confidence = ~50-55% of response characters. Tokens: 35-50% (JSON punctuation
and numbers tokenise denser per character than ids), **central estimate 40%**.
Not saved: options text, labels, annotations, `selected`, `control_type`.

**Latency model.** `T = F + out/r`, `F` = per-call fixed cost (queue, time to
first token, input prefill), `r` = output rate. `F` is **unmeasured**:
the three measured models cannot separate slope from intercept (flash
~270 tok/s, lite ~470 tok/s, 4o-mini ~94 tok/s on a 1.6k response). Table for
the flash non-thinking run (73 s, 19.7k tokens), assuming a 40% output cut,
`chunk_max_anchors` splitting into 4 equal chunks run truly concurrently, no
fixed per-chunk preamble, and no provider-side queueing:

| F (s) | measured | after T5 (single call) `43.8+0.4F` | after T5 + T7 (4 chunks) `10.95+0.85F` |
|---|---|---|---|
| 0 | 73 | 44 | 11 |
| 10 | 73 | 48 | 20 |
| 20 | 73 | 52 | 28 |
| 30 | 73 | 56 | 37 |

Same arithmetic for flash-lite (47 s): single call `28.2 + 0.4F`. Reading it:
(i) the floor does not eat the contract saving (it costs `0.4F`); (ii) the
floor does bound chunking: asymptote is `F`, returns flatten above ~4-6 chunks;
(iii) each assumption, if violated, makes the estimate a lower bound (queued
concurrent requests, serialised retries under backoff, a per-chunk preamble).
**The larger item is thinking:** turning default thinking off took 187 s to 73 s
and 51.6k to 19.7k tokens, more than T5 and T7 combined, so T1's levers table
is the first-order result. Do not quote dollar savings: no prices were used.
Chunking raises input tokens roughly N-fold (4.1k prefix + context per chunk);
it is a latency lever, not a token lever.

## 11. Cuts (explicitly NOT in 0.6.0)

- **Resolver derivation of source_elements from label/option text** (text
  matching of document text; non-deterministic under duplicate labels).
- **Row shorthand refs** (`R3:12` = the anchor row's hypothesis): structural
  but needs a pre-resolution expansion step; revisit after G1.
- **Hypothesis ids in the prompt** (the prompt never shows
  `layout.hypotheses`): a different contract, a larger prompt; not now.
- **Near-match reuse / delta authoring** (equal geometry, anchors differing in
  <= X% of rows). Needs a near-match key, row alignment (`page_anchor_multiset`
  returns counts, not positions) and a row-subset projector; tuned on one file.
  0.6.0 only prints the profiler's integers; decide for 0.7.
- **Gap-fill second pass** for unbound anchors (a follow-up call with only the
  uncovered rows): a 0.7 idea once coverage exists and has been read on real
  data.
- **Few-shot examples** (T6c): only if T6's sentence under-delivers.
- **`author_page` unit** for reuse + chunking together: until a workbook needs
  both.
- **Duplicate-label check** and **residuals redefinition**: later additions to
  the block / a behaviour change.
- **Capability flags on `LLMClient`**, built-in provider clients in the
  package, a default `max_tokens`, changing the default `params`.
- **Ensembling / vision tier / auto-tuned thresholds / streaming.**
- **`address` / `include_address`**: unchanged from 0.5.0.
- **A separate `openai-compatible` provider flag** (it is `--base-url`), and
  attribute sniffing beyond `status_code`/`code`.
